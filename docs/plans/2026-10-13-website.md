# summonvans.in — Website Plan

**This file is the one place.** Everything about the site is decided here: what it says, how it looks, what is still to do, and what is waiting on Vedansh. Instructions are not given in chat, in commit messages or in a second document. If something is agreed anywhere else, it is written here before anyone acts on it, and if this file and the site disagree, this file is right and the site is fixed. The single exception is the wording of the privacy page, which lives in `website/content/privacy.md`.

**Goal:** One page at `summonvans.in` that shows what VANS is in the first five seconds, lets a visitor try the guide and the panel in the browser, and ends with one action: ask to join the testers.

**The one idea:** VANS teaches. Ask how to do something and it shows you, on your own screen, one step at a time, while you do it. That is the lead. That it can also do the job for you is the second thing said, never the first. Every heading, every demo's default and the order of the page follow from this. If a line of copy makes VANS sound like something that takes over the Mac, rewrite it.

**Who it is for:** someone on a Mac who has never heard of VANS, arriving from a link. Second reader: a reviewer of the startup-program application, who will spend about a minute on it.

**What it is not:** a download page (there is no tester build yet), a docs site, a pricing page, or a blog. Do not add those.

**Tech stack:** Vite, vanilla TypeScript, plain CSS. No UI framework. This is the same stack as the panel (`ui/`), which lets the panel's own stylesheet, `pill.ts` and `dots.ts` be copied across and behave identically.

**Where it lives:** a `website/` folder at the top of this repository, beside `cmd`, `docs`, `internal` and `ui`. It has its own `package.json` and shares nothing with `ui/` at build time.

**Hosting:** Cloudflare Pages, connected to this repository. Root directory `website`, build command `npm run build`, output `dist`. Build watch paths set to `website/*`, so a change to the engine or the panel does not rebuild the site. DNS is already on Cloudflare (AGY.md, G9).

## Global constraints

- **This repository stays private.** Only what the build writes to `website/dist` is ever public. Nothing under `website/` may read from outside it at build time: no imports from `ui/`, `internal/` or `docs/`, and no reading of `.env`. What the site needs from the panel (the token sheet, `pill.ts`, `dots.ts`) is copied into `website/src` and kept there.
- **Nothing private in the bundle.** Before each pull request, search `website/dist` for anything that should not be public: keys, local paths, names from `docs/ideas.md`. Source maps are not published.
- **Only what is true.** Every claim on the page must be something VANS does today. The source of truth is `AGY.md` and `docs/decisions.md` in the VANS repository. No invented user counts, quotes, logos, awards or benchmarks. If a section needs something that does not exist yet, leave the section out.
- **No trackers, no third-party requests.** Fonts are self-hosted. No analytics script unless Vedansh asks; if he does, Cloudflare Web Analytics only (no cookies).
- **Commits** are signed off (`git commit -s`) and read as written by Vedansh. No tool or generator attribution in commits, pull requests, code comments, the README or the page footer.
- **No comments in new code** beyond what a reader could not work out. Match the panel's code style.
- **Do not attach the domain or go live** without Vedansh saying so. Preview deployments on the `*.pages.dev` address are fine.
- **The name.** `VANS`, in capitals. The full form is "Visual Agent Navigation System" (D-222), and it is for official documents only. On this site that means exactly two places: once in `website/content/privacy.md`, and once in the terms when they exist. The main page never spells it out: not in the hero, the footer, the title, the meta tags, the share image or any demo's text. The older form, "Vedansh's Agent Navigation System", appears nowhere on the site. No shoes, no vehicles, no checkerboard patterns, anywhere. A clothing brand owns the lowercase word.

## The look

Take it from the panel, not from other sites. The panel's design is recorded in D-212 and D-216.

**Colour** (copy the tokens from `ui/src/styles.css`, `:root` and `:root[data-theme="dark"]`):

| Token | Dark (default) | Light | Used for |
|---|---|---|---|
| ink / background | `#10110E` | `#F3F4EE` paper | page background |
| text | `#F3F4EE` | `#10110E` | body |
| volt | `#FFD23F` | `#FFD23F` | VANS itself: the pointer, the ring, the one primary button |
| write | `#FF4867` | `#E8203F` | only "this changes something" |
| line / fill / mute | as in the stylesheet | as in the stylesheet | hairlines, quiet surfaces, secondary text |

Two rules that carry meaning and must not be broken:

1. **Volt is VANS.** Use it sparingly: the pointer, the ring, the primary button, one accent per screen.
2. **Red means something outside VANS is about to change.** It appears only in the confirm demo. Never as decoration, never for errors in general, never in the hero.

**Light is the default** (changed 2026-10-13; the first build was dark first). A light and dark switch sits in the header where it can be seen, not only in the footer, and stores the choice in `localStorage` under a try/catch. A visitor whose system is set to dark still gets light on a first visit; only their own choice on the switch changes it. Light must be designed, not inverted: volt on paper is unreadable as text, so use the panel's light pill tokens (`--pill-a/b/c`) and keep volt for fills and marks.

**Type:** the panel uses the system stack. Keep `-apple-system` first so it is native on a Mac, and self-host Inter (variable) as the fallback for everyone else, plus a monospace for keys and the readout. Sizes: one large display size for the headline (clamp between 40px and 76px), 17 to 19px body, 12 to 13px mono kickers in capitals with letter-spacing, as in `.kicker`.

**Surfaces:** panel radius 20px, the `--edge` inset hairline, glass tint 0.86 over a soft blur. Keep borders at half a pixel where the display allows.

**Motion:** the panel's spring, `cubic-bezier(0.2, 0.8, 0.2, 1)`. Things arrive in 240 to 320ms and never bounce. One moving thing at a time. With `prefers-reduced-motion`, everything holds still and state changes cut instead of animating.

**Colour in the visuals** (added 2026-10-13). The first build read as monochrome. The page should be warm and colourful in its pictures while the two meaning rules above stay exactly as they are.

- **Where colour goes:** inside the drawn windows and demos, in the request cards, and in soft washes behind sections. Not in body text, not in headings.
- **An illustration palette,** used only for pictures and never for meaning: blue `#4C8DF6`, teal `#22B8A7`, green `#3DBE6B`, violet `#8B6CF6`, with soft tints of each for backgrounds. No reds, pinks or oranges: on this site red means one thing.
- **The drawn Mac window should look like a real, lit window:** coloured traffic lights, coloured sidebar icons, real-looking content. If the hero guide teaches changing the wallpaper, the wallpaper tiles are the colour: a grid of vivid thumbnails, and the desktop behind the window changes when the visitor picks one. That is the most colourful thing on the page and it is also the lesson.
- **Request cards** each carry a small coloured mark for their kind (showing, reading, writing text, files), from the illustration palette.
- **Section backgrounds** may carry a very soft colour wash or blurred shape in light mode. In dark mode the same shapes glow faintly. Nothing animated behind text.

**Premium here means restraint in everything but the pictures:** generous space, one idea per screen, the real product drawn exactly, nothing glossy that the product does not have. No stock illustration. No emoji.

## Page structure

Six sections, in this order. Copy is a draft; keep its plainness if it is rewritten.

### 1. Hero

- Kicker (mono, volt dot): `VANS · FOR MAC`
- Headline: **Ask how. It shows you, right on your screen.**
- Sub: VANS is a guide you summon with ⌥Space. Ask how to do something and it points at the next thing to click, in the app you are already in, and waits while you do it. When you would rather not, it can do the job for you.
- Primary button (the living pill): **Join the testers**
- Secondary text link: Windows? Tell me.
- Below: the **guide demo** (interactive element A). It is the hero image. There is no screenshot. It starts in `Show me` mode.
- Hint under the demo, in mono: `Click the ringed control, or press ⌥Space for the next step`

### 2. Shown how, or done for you

Kicker: `TWO WAYS`. Heading: **Learn it once. Or hand it over.**

Two short paragraphs, the first given more room than the second.

- *Show me how.* VANS puts a ring on the next control and waits. You do the clicking, so the next time you know where it is. It moves on when the window shows you did the step. Leave the app and the guide waits for you; come back and it is on the same step.
- *Do it for me.* The same steps, carried out by VANS where you can watch. It shows the plan first, and anything that changes something waits for you to confirm.

One line under both, because it is the bridge between them and it is real: **Part way through being shown, you can hand a step over.** When a step is typing something in, the guide offers `⌘↵ Do it for me`, and `⇧⌘↵` for the rest like it.

Then the **live panel** (interactive element B), opened on a "how do I" request.

### 3. What you can ask

Kicker: `ASK`. Heading: **Start with "how do I".**

A grid of eight request cards. Each card is a real request in the visitor's words, with one line saying what happens. The first row is all teaching; the second row is what else it does. Clicking a teaching card plays it in the guide demo; clicking any other plays it in the live panel.

| Request | What happens |
|---|---|
| how do I change my wallpaper | Tells you which app it lives in, then points at each control in turn |
| show me where the search box is | Points at it on your screen and waits for you |
| how do I add a reminder for tomorrow | Walks you through it in Reminders, and offers to type the text for you |
| what does this error say | Reads what is on screen and explains it in plain words |
| what is this page about | Reads the page in front and answers in the panel |
| translate "good morning, see you at three" to Hindi | Works on the quoted or selected text and hands it back to copy |
| move the screenshots on my Desktop into a folder called Screenshots | Shows what it will move, waits for you, and can put every file back |
| in 1 minute remind me to stretch | Brings it back at the time. It does not run things behind your back |

### 4. You stay in charge

Kicker: `CONTROL`. Heading: **Nothing changes until you hold the key.**

Four plain statements, each a short line with one supporting sentence. No icons needed.

- **It asks first.** Anything that changes a file, a setting or an app waits for you to hold Return. A press is not enough.
- **It can be undone.** File moves and typed text go into a record, and each can be put back.
- **It does not open or switch apps on its own.** If a step needs another app, opening it is a step it shows you.
- **You set the limits.** Places it must never touch, things it must always ask about.

Beside the list: the **confirm demo** (interactive element C).

### 5. What it sees and keeps

Kicker: `PRIVACY`. Heading: **Plain about what leaves your Mac.**

Short paragraph and three bullets. This section needs Vedansh to confirm each line before launch (see "To confirm").

- VANS looks at a window only when you ask it something about that window.
- When text is sent to a model to work on, the panel says so in the answer.
- Of what you have asked, it offers back only the last three. Routines, facts and rules are kept because you told it to keep them, and each can be removed.

### 6. A note, and the ask

Kicker: `WHY`. A short note from Vedansh in the first person, four or five sentences, signed. Draft for him to rewrite:

> I built VANS because I was tired of looking up how to do small things on my own Mac: where a setting lives, which menu has the thing I need. A video shows you someone else's screen. I wanted something that would point at mine and wait while I did it, so that the next time I would just know. It can also do the job for you when you do not care to learn it, and it shows you exactly what it is about to do first. VANS is early. A few people are testing it, and I would like you to be one of them.
>
> — Vedansh

Then the living pill again: **Join the testers**, and the line `vedansh@summonvans.in` in mono.

### Privacy page

A second page at `/privacy`, linked from the privacy section ("Read the full privacy page") and from the footer. Its text is `website/content/privacy.md`, written by Vedansh; render it as it stands, in the site's type and both themes, at a readable measure of about 68 characters. Do not reword it, shorten it or add claims to it. It will be edited often, so keep the text in that one file and build the page from it.

### Footer

Wordmark, `© 2026 Vedansh Saini`, a link to the privacy page, the theme switch, and one line: `VANS is not affiliated with any clothing or footwear brand.` No link columns.

## Interactive elements

All of them are scripted and run entirely in the page. Nothing calls a server or a model. Each must work with mouse, touch and keyboard, and each must leave the page readable if JavaScript is off.

### A. The guide demo (hero)

A drawn Mac window (a neutral settings-style window, not a real app's artwork) with three steps to complete: for example, open a sidebar row, flip a switch, press a button.

- A volt ring with the step number sits on the next control. A volt pointer with a small `VANS` tag glides to it. A card says the step and the keys: `⌥Space Next · esc Stop`.
- **The visitor does the step.** Clicking the ringed control advances it, as the real guide does. ⌥Space also advances.
- After the last step: a tick on the ring and `That is all of it`, then it resets.
- Around the control the window dims slightly (D-091). No ripple, no rotating pointer.
- One of the three steps types a value. On that step the card also offers `⌘↵ Do it for me`; taking it shows the pointer typing the value, then the guide carries on with the next step as the visitor's again.
- A small switch above the window, `Show me` / `Do it for me`. It starts on `Show me` and returns to it on reset. In the second mode the pointer does the three steps by itself and the caption reads `esc to stop`.
- The steps should teach something a visitor could not already guess, so that finishing the demo feels like having learned where a thing is.

### B. The live panel

A faithful copy of the real panel: 720px wide at most, radius 20, the persistent field at the top, the readout beside it, the foot with key hints. Build it from the panel's own CSS classes so it cannot drift.

- **Summon:** pressing ⌥Space anywhere on the page, or clicking the hint, springs the panel in. `preventDefault` only for that exact chord. On touch devices the panel is simply there.
- **Ask:** the field types out a "how do I" request by itself on first view, then accepts clicks on the suggestion chips under it (the requests from section 3). A teaching request ends with the panel stepping aside and the guide demo taking over, which is what the real panel does. Free typing is allowed; anything not in the script answers: `This is a demo. In the real panel, VANS would work that out.`
- **States to show, in order:** asking → working (the dot field animates, from `dots.ts`) → answer. The readout shows a time like `1.4 s`, and `Remembered · instant` when the same request is run a second time. That second-run detail is real behaviour and worth showing.
- **Escape steps back:** answer → field with words → empty field → dismissed, exactly as D-212 describes.
- **One request is a write** (the screenshots one): it must hand over to element C's behaviour inside the same panel.
- This element comes second on the page. Do not put it in the hero.

### C. The confirm demo

The panel in its confirm state: a red ring round the whole panel, the plan listed (`Create folder Screenshots`, `Move 3 files`), and the button `Hold to confirm`.

- Holding the button, or Return, fills it over 750ms. Letting go early cancels and the fill drains.
- On completion: `Done · 3 files moved`, with an **Undo** button. Undo plays the reverse and says `Put back`.
- This is the only place red appears on the site.

### D. The living pill

Copy `ui/src/pill.ts` and its CSS block. Used for the two `Join the testers` buttons and nowhere else (D-216: one control with the living treatment). The glow trails the pointer; with reduced motion the gradient holds still.

### E. Quiet touches

- The hero background is the dot field at very low contrast, drifting, brightening a little near the pointer. It must cost almost nothing: pause it when the tab is hidden or the hero is off screen.
- Sections fade up by 12px once, on entering view. Nothing replays on scroll back.
- Key caps (`⌥`, `Space`, `esc`, `↵`) are real `<kbd>` elements styled as in the panel, and they depress when the visitor presses that key.

## The one action

`Join the testers` opens mail to `vedansh@summonvans.in` with the subject `VANS tester` and a two-line body asking which Mac and macOS version they use. The Windows link does the same with the subject `VANS on Windows`.

A form would convert better than a mail link, and needs a small server function to receive it. That is a later change; do not build it in the first version.

## Quality bar

- Looks right from 360px to 1600px wide. On a phone the panel scales down and the guide demo becomes tap-driven.
- Keyboard: every demo reachable and operable by Tab, Return, Space and Escape, with a visible focus ring.
- Contrast at least 4.5:1 for text in both themes.
- No layout shift on load. Reserve the panel's height before it mounts.
- JavaScript under 60KB gzipped in total; no runtime dependencies beyond what is copied from the panel.
- Lighthouse on mobile: 95 or better for performance and accessibility.
- `<title>`, description, Open Graph and Twitter card tags, a favicon in ink and volt, and a 1200×630 share image drawn from the hero.
- `robots.txt` allows indexing; a one-entry `sitemap.xml`.
